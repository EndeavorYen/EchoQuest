# EchoQuest 家庭魔法冒險重製設計

日期：2026-07-11

## 目標

將目前以答題扣 Boss 血為主的介面，重製為可由 2 歲、5 歲與成人輪流遊玩的短篇魔法冒險。第一階段交付一個 5–8 分鐘、可完整通關的「森林救援」垂直切片，先證明遊戲好玩、教學自然且語音可靠，再增加地圖與內容。

## 成功條件

- 玩家能在 10 秒內理解目前任務與可做的動作。
- 三個房間具有不同操作，不是重複答題換背景。
- 2y、5y、成人使用同一趟家庭冒險，但各自有合適的施法方式。
- 正確答案會改變角色或場景；錯誤答案提供逐步提示且不重置整關。
- 語音在支援的 Chrome／Edge localhost 或 HTTPS 環境可完成「開始聆聽 → 顯示辨識結果 → 玩家確認 → 施法」。
- 語音不支援、權限被拒或辨識失敗時，拼字／打字仍可立即完成任務。
- 桌面與 390px 手機寬度皆能在首屏看到任務、場景與主要操作。

## 核心體驗

### 家庭共用冒險

冒險地圖、救援角色、魔法卡與寶箱由全家共享。每個房間可切換目前玩家；學習熟練度仍依玩家類型調整挑戰，不要求登入或建立多人帳號。

### 森林救援任務

1. **探索房：找回治療蘋果**
   - 物品直接出現在森林場景。
   - 2y 聽音後認圖；5y 看首字母提示選物；成人使用聽音或限時辨識。
   - 成功後取得治療魔法，樹木與角色產生可見反應。

2. **魔法房：修復斷橋**
   - 每個正確字母成為一塊橋板。
   - 2y 依圖形或顏色拖曳；5y 排列字母；成人打字或使用語音。
   - 錯誤時先高亮可用線索，再降低選項數，不立即公布完整答案。

3. **救援房：反制森林巫師**
   - 敵人輪流提示火焰、重擊或詛咒意圖。
   - 玩家從火球、護盾、治療選擇反制；學習挑戰決定魔法是否成功。
   - 勝利後救出角色並開啟寶箱，不以單純歸零血條作為唯一回饋。

## 年齡與教學層級

| 玩家 | 主要操作 | 教學策略 | 失敗處理 |
| --- | --- | --- | --- |
| 2y 圖像 | 聽音、認圖、點選或簡單拖曳 | 兩個大選項起步，熟悉後增加至三個 | 不扣血；放大正確特徵並重播發音 |
| 5y 單字 | 字母排列、缺字填空、嘗試打字／語音 | 看圖 → 首字母 → 完整回想逐步撤除提示 | 清除錯誤組合並提供下一個字母線索 |
| 成人／家長 | 快速打字、聽音辨字、語音 | 較短反應時間與較少提示 | 保留任務進度，立即重試或切換輸入 |

每個任務集中練習 4–6 個單字。較弱單字會在後續物品、對話與敵人弱點中自然重現；熟練單字則提升魔法效果，避免只顯示抽象熟練度數字。

## 視覺與操作

- 採用已確認的 A「場景先行」方向，世界與角色佔主畫面至少 70%。
- 左上僅顯示目前任務；右上顯示目前玩家；底部顯示 2–3 個可用魔法。
- 題目嵌入場景物件，避免三欄儀表板、卡片套卡片與長篇說明。
- 美術採明亮手繪奇幻童話風，使用清楚輪廓、可辨識表情與多色場景。
- 強動畫只用於施法、救援、開寶箱與房間轉場；支援 `prefers-reduced-motion`。
- 手機保留完整場景，主要操作固定在拇指可及的底部區域；幼兒觸控目標至少 72px。

## 語音輸入可靠性

語音維持瀏覽器原生 Web Speech API，不增加服務或依賴。流程採單次明確錄音，不使用持續自動重啟：

1. 玩家點擊麥克風並觸發瀏覽器權限要求。
2. UI 顯示正在聆聽、可取消與超時狀態。
3. 最終辨識文字顯示給玩家確認，確認後才送出答案。
4. `no-speech`、`audio-capture`、`not-allowed`、`network` 與不支援狀態提供具體訊息。
5. 任何失敗都保留房間、單字與其他輸入方式，不自動判錯或扣除資源。

語音驗收包含支援狀態、權限拒絕、無聲、重試、取消、結果確認、切換玩家後不沿用舊結果，以及元件卸載後不重啟辨識。

## 技術結構

保留 React、TypeScript、現有字庫、進度儲存與語音 hook，不新增遊戲引擎。

- `App.tsx`：任務流程、玩家切換與房間畫面組裝。
- `game/`：純函式描述房間、敵人意圖、魔法效果與下一步狀態。
- `hooks/useSpeechRecognition.ts`：單次語音辨識生命週期。
- `learning/` 與 `persistence/`：延用現有熟練度與 localStorage。
- `public/assets/generated/`：重用既有素材；垂直切片確認後才批次生成新地圖與角色圖。

任務資料流為「房間狀態 → 年齡挑戰 → 玩家輸入 → 答案／魔法結果 → 場景反應 → 下一個事件」。非同步語音結果必須包含目前房間與單字識別，過期結果不得改變新題目。

## 錯誤與復原

- 字庫不足時顯示家長可處理的提示，不進入空白場景。
- 圖片載入失敗時顯示可辨識文字／符號退路。
- localStorage 損壞時回到預設進度，不阻止開始遊戲。
- 語音錯誤不影響主要輸入與冒險狀態。
- 玩家離開或重新整理後恢復任務起點，不恢復半完成的錄音或動畫。

## 驗證

- 純函式測試：三房間轉換、年齡挑戰、魔法反制、提示升降級。
- React 測試：三種玩家各自完成任務、輪流切換、錯誤提示、勝利收藏。
- 語音測試：支援、拒絕、無聲、重試、確認、過期回呼與 fallback。
- 瀏覽器實玩：桌面與 390×844 手機完成整個森林救援流程。
- 視覺回歸：首屏任務可見、無水平溢出、文字不遮擋場景、主要操作可觸及。
- 完成前執行完整 Jest、TypeScript build、`git diff --check` 與瀏覽器 console 檢查。

## Issue 追蹤與完成定義

為本次重製建立一個總追蹤 issue，並依實作拆成最少必要項目：核心三房間、年齡挑戰、場景 UI／動畫、語音可靠性、測試與文件。每個 issue 必須有可重現步驟或驗收條件。

「resolve all issues」指本次重製建立的追蹤項目。只有在對應測試、實玩證據與文件完成後才關閉；既有無關 issue 不會被擅自關閉。

## 第一階段不做

- 不建立帳號、雲端同步或線上多人。
- 不一次製作多張地圖或大量劇情。
- 不增加遊戲引擎、後端語音服務或新狀態框架。
- 不把家長報表與字庫管理放回主要遊戲 HUD。
