# EchoQuest 家庭接力救援重設計

日期：2026-07-11

## 目的

把目前「答題後換房間」的森林救援，重做成可由 2y、5y 與成人在同一局中接力完成的短篇童話冒險。每個學習動作都要直接改變場景；每一局要因路線、事件與詞彙而不同，並能在中斷後精準續玩。

## 目標與完成條件

- 一局為三個隨機救援事件加 Boss，約 5–8 分鐘。
- 任何時間可切換 2y 圖像、5y 拼字與成人打字／語音；目標單字、事件與已完成的世界變化不重置。
- 答對立即造成可見世界結果，例如路徑亮起、橋板完成、護盾擋下危機或角色抵達安全處。
- 每局的事件、危機、單字與獎勵由單一任務種子建立；重新整理或隔天回來能恢復同一個事件與單字。
- 完成整局後才建立新的任務種子，讓下一局有不同的事件順序與詞彙組合。
- 語音輸入必須明確顯示權限請求、聆聽、辨識結果、確認與錯誤；任何語音問題都不阻止拼字／打字完成任務。
- 桌面與 390×844 手機首屏都要先看到場景、當前危機和主要操作，不得出現水平溢出或任務標題被操作面板遮住。

## 玩家與共同進度

全家共用一份任務進度、地圖、角色救援狀態與收藏，不設個人競賽分數。

| 模式 | 操作 | 同一事件中的效果 |
| --- | --- | --- |
| 2y 圖像 | 大型認圖、點選或簡單拖曳 | 找到目標物、啟動路徑或拿到建材 |
| 5y 單字 | 字母排列、缺字、嘗試語音 | 每個正確字母生成橋板、符文或護盾片 |
| 成人／家長 | 快速打字或已確認的語音 | 完成施法、選擇反制或加速同一個世界動作 |

切換模式只替換目前事件的輸入介面。未提交的字母、輸入文字與錄音不必跨模式保存；事件、目標字、已建立的場景物件與獎勵必須保存。使用過不同模式的家庭可累積純視覺的「魔法連鎖」收藏，但單人也能完整通關。

## 任務迴圈

每次新任務從四個非 Boss 模板中抽三個，最後固定進入 Boss：

1. **偵察找路**：辨識單字後，藤蔓退開、石頭發光或安全路徑出現。
2. **魔法建造**：字母或答案直接成為橋板、繩索、符文。
3. **護送前進**：找出安全路或施放保護，讓同伴穿越危險地形。
4. **避險反制**：辨識危機並完成對應的詞彙動作，阻止掉落物、荊棘或詛咒。
5. **Boss 救援**：任務種子決定三段危機意圖；完成詞彙充能後選擇火球、護盾或治療。正確反制改變 Boss 與救援現場，而不只是顯示訊息。

錯誤答案不重置事件。2y 不受時間限制；5y 會取得下一字母或較少選項；成人可看到可選的短反應挑戰，但不影響全家繼續遊玩。

## 任務隨機性與詞彙

亂數只在建立新任務時使用，並儲存在任務種子中。渲染、換人、重整與語音回呼不得重新抽題。

- 先從啟用詞彙依既有學習進度選出優先候選：新字、到期字、較不熟字優先。
- 用任務種子打散同等優先的候選，且避免同一局或相鄰兩局立即重複同一字。
- 任務計畫儲存 `wordId`，不儲存複製的字面資料；字庫更新後仍能追蹤同一個詞彙。
- 若已存任務的詞彙被停用或刪除，安全挑選另一個合格詞彙並立即寫回任務計畫。
- 初版的變化來自可重現模板組合，不建立無邊界的即興關卡生成器。後續新增模板、場景與詞彙包即可擴大變化量。

## 續玩與本機儲存

新增 `echoquest_adventure_v2`，以 `localStorage` 保存一個未完成的任務。

任務至少包含：版本、種子、建立時間、事件清單、目前事件索引、每個事件的世界進度、目前 `wordId`、Boss 意圖索引、共享收藏與已使用模式。每次事件完成、Boss 回合結束、模式切換後的有效狀態變化，都更新儲存值。

App 載入時驗證資料：

- 有有效的未完成任務時，提供「繼續救援」並恢復到同一事件。
- 沒有任務、任務完成或資料損壞時，建立新任務。
- 不恢復未送出的拼字、輸入文字、麥克風請求或動畫，避免把玩家卡在半完成的瀏覽器狀態。

## 場景與美術

採用已選定的 A「場景導向童話」版面。

- 世界至少佔首屏 60%；上方只保留精簡的任務進度與目前接手者。
- 下方固定接力操作列，讓玩家一鍵切換 2y、5y、成人；場景與目標字不離開視野。
- 不使用佔主畫面的白色題目卡、每關重複的傳送門，或單純背景換色來表示進度。
- 首發素材包包括果園、斷橋、河岸護送、荊棘祭壇四個完整不透明背景，以及一致風格的角色與互動物件透明素材。
- ImageGen 只用於場景、角色、危機與互動物件；單字圖繼續由字庫提供，避免將特定單字烤死進場景。
- 動畫限於路徑揭露、橋板生成、護盾反制、救援與開箱，並遵守 `prefers-reduced-motion`。

## 語音輸入

延用瀏覽器原生 Web Speech API 和現有單次辨識流程，不新增語音後端。

點麥克風後，UI 先進入「正在請求麥克風權限」；`onstart` 後才進入「聆聽中」。接著顯示最終辨識文字，玩家確認後才送出答案。`not-allowed`、`no-speech`、`audio-capture`、`network`、不支援與逾時都提供可行的文字回饋，拼字／打字始終可用。

換人、換事件、任務恢復或元件卸載時停止辨識並忽略過期回呼。真實瀏覽器試驗顯示 API 在 localhost 可用、隔離 Edge 的麥克風權限初始為 `prompt`；因此「權限請求中」是必要 UI 狀態，而不是只在錯誤後才顯示訊息。

## 程式結構與資料流

維持既有 React + TypeScript 架構，避免新增引擎或狀態框架。

- `web/src/game/adventure.ts`：由固定三房狀態改為純函式的任務建立、種子抽選、事件推進、Boss 反制與恢復驗證。
- `web/src/persistence/adventureStorage.ts`：讀寫與驗證進行中的任務；與既有詞彙／學習進度儲存分開。
- `web/src/App.tsx`：組合場景、底部接力操作、模式切換、恢復入口與輸入方式。
- `web/src/hooks/useSpeechRecognition.ts`：增加權限請求中的明確狀態，保留既有一次辨識、取消與過期回呼防護。
- `web/src/learning/progress.ts`：沿用現有複習排名，提供任務建立時的詞彙候選。

資料流為：`新任務或載入任務 -> 取得目前事件與 wordId -> 目前玩家輸入 -> 純函式更新事件與世界狀態 -> localStorage -> 下一事件或 Boss`。任何非同步語音結果都必須對應目前任務、事件與單字，否則忽略。

## 測試與驗收

### 自動測試

- 同一種子、相同詞彙與進度一定產生相同任務。
- 不重複的事件模板與受控詞彙抽選。
- 模式切換保持事件、`wordId`、共享世界狀態。
- 任務存檔、重新載入、損壞資料與刪除詞彙的恢復。
- 每個事件的正確、錯誤與提示／恢復路徑。
- Boss 三段危機與結局。
- 語音權限請求、拒絕、結果確認、過期回呼與 typing fallback。

### 瀏覽器實玩

- 用 Chrome CDP / 隔離 Edge 完成 2y -> 5y -> 成人的中途接力，以及重整後續玩。
- 390×844 與桌面截圖檢查：場景改變可見、任務標題與操作不重疊、無水平溢出、操作可達。
- 實體 Chrome 或 Edge 麥克風手動驗證：允許權限、聆聽、辨識、確認、拒絕與取消。
- console 不得有應用程式錯誤；Tailwind CDN 警告為既有技術債，若本次變更觸及建置再一併處理。

## 範圍外

- 帳號、雲端同步、線上多人與個人排行榜。
- 後端語音、LLM 即時生成劇情、無上限地圖生成。
- 一次交付多個主題地圖；首發先把荊棘森林做成值得重玩的完整垂直切片。
